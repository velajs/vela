# New Vela API scaffold

Use the workspace's aligned Vela/Hono versions. For Workers, start with the Cloudflare package's `examples/live-todo` when live queries or Durable Objects are required; the small HTTP-only shape below needs no binding wrapper modules.

## Build configuration

Install `@velajs/vela`, `@velajs/cloudflare`, `hono`, and an application schema library such as Zod 4.4+. Add TypeScript and Wrangler as development tools. Preserve generated native Worker environment types from `wrangler types`.

Decorator metadata requires a compiler that emits it. A TypeScript build is sufficient:

```json
{
  "type": "module",
  "scripts": {
    "build": "tsc -p tsconfig.json",
    "dev": "wrangler dev",
    "deploy": "wrangler deploy"
  }
}
```

```json
{
  "compilerOptions": {
    "target": "ES2024",
    "module": "ESNext",
    "moduleResolution": "Bundler",
    "experimentalDecorators": true,
    "emitDecoratorMetadata": true,
    "strict": true,
    "skipLibCheck": true,
    "outDir": "dist",
    "rootDir": "src",
    "lib": ["ES2024", "WebWorker"]
  },
  "include": ["src/**/*.ts", "worker-configuration.d.ts"]
}
```

Point Wrangler at the emitted entry file and run the build before bundling:

```json
{
  "name": "my-vela-api",
  "main": "dist/main.js",
  "build": { "command": "pnpm build" }
}
```

Add the application's compatibility date and native bindings to its Wrangler configuration. Generate matching environment declarations. Vela includes its metadata polyfill; no separate `reflect-metadata` dependency is needed.

## `src/env.ts`

```ts
import { InjectionToken } from '@velajs/vela';

// Env comes from worker-configuration.d.ts generated by Wrangler.
export const ENV = new InjectionToken<Env>('app.Env');
```

## `src/app.module.ts`

```ts
import { Controller, Endpoint, Get, Module, defineEndpoint } from '@velajs/vela';
import { z } from 'zod';

const hello = defineEndpoint({
  input: z.object({}),
  output: z.object({ message: z.string() }),
});

@Controller('/app')
class AppController {
  @Get()
  @Endpoint(hello)
  hello(_input: ReturnType<typeof hello.input.parse>) {
    return { message: 'Hello from Workers' };
  }
}

@Module({ controllers: [AppController] })
export class AppModule {}
```

## `src/main.ts`

```ts
import { createCloudflareWorker } from '@velajs/cloudflare';
import { AppModule } from './app.module.js';
import { ENV } from './env.js';

export default createCloudflareWorker(AppModule, {
  envToken: ENV,
  globalPrefix: '/api',
});
```

Inject bindings with `@Inject(ENV)` and the generated `Env` type. Factories use `defineProvider(TOKEN, { inject: [ENV], useFactory: env => ... })`; even a zero-dependency factory supplies `inject: []`.

For a platform-neutral application use `await VelaFactory.create(AppModule)` and export its fetch handler. Node uses `serve({ fetch: app.fetch })` from `@hono/node-server`; keep that runtime-specific server entry separate from the Worker entry.

## Introspection and RPC

Install `@velajs/cli` when introspection/codegen is needed. Its `vela.config.ts` uses `defineVelaConfig({ rootModule: AppModule, createApp })` from `@velajs/cli/config`. Make `createApp` construct the application with the appropriate test/tooling environment and adapters; never invent platform bindings with a type assertion.

Run `vela route list` and `vela openapi dump` to inspect the contract, then `vela client generate --out src/api.generated.ts --strict`. The frontend imports only the generated `AppType` and Hono `hc` from `@velajs/client/http`. See `references/openapi.md`, `references/cloudflare.md`, and `references/live-queries.md` for the complete wiring.
